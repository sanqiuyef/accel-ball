# 加速球自测记录

- 日期：2026-11-18
- 系统：Windows 10 x64 19045.6466，单屏 1920×1080，DPI 100%
- 编译器：MSVC 14.44.35207（VS2022 Build Tools）
- 打包：Inno Setup 6.7.3（用户级安装）

## 1. 构建与 manifest

```text
build\build.bat dev
→ dist\AccelBall-dev.exe（242,688 字节，manifest asInvoker）

build\build.bat release
→ dist\AccelBall.exe（242,688 字节，manifest requireAdministrator）

ISCC.exe installer\accel-ball.iss
→ dist\AccelBall-Setup-1.1.0.exe（2,246,741 字节）
```

manifest 提取（`mt.exe -inputresource:...;#1`）：

- 发布版：`requireAdministrator = true`，`PerMonitorV2 = true`，版本 `1.1.0.0`
- 开发版：`asInvoker = true`，`PerMonitorV2 = true`

## 2. 尺寸与 UI

- 按用户反馈经历 124px → 52px → 74px 两次调整；最终球径 74px，为原 124px 的 60%。
- 百分比字号 18px（粗体），上下行字号 9px，网速使用 `K/s`、`M/s` 紧凑单位。
- 同一时刻用 `GlobalMemoryStatusEx` 核对：程序显示 48%，系统返回 `dwMemoryLoad = 48`。
- 限速下载期间实际截到 `↓ 22.3M/s`，74px 下网速清晰可读。
- 1.1.0 启动后实测：Working Set 11,868 KB；旧版长跑实例曾观察到约 59 MB RSS / 39 MB private / 16 线程，疑似 GDI+ 字体缓存或线程累积，1.1.0 尚未做长跑复测。

## 3. 双击清理

- 在 74px 圆球百分比区域发送 `WM_LBUTTONDBLCLK`。
- 约 1.5 秒后截图显示「释放 768M」，内存从 33% 降到 31%，程序未退出。
- 清理在后台线程执行；执行期间显示「清理中…」，完成后显示释放量约 3 秒。

## 4. 贴边、悬停与命中

- 拖到右边缘：30×74 竖向条，显示「点 + 竖排内存 + 百分比」。
- 拖到上边缘：74×30 横向条，显示「点 + 内存 xx%」。
- 鼠标移入贴边条：展开为 74×74 圆球；移出约 0.45 秒后恢复贴边条。
- 悬停展开时，球外那段贴边条区域绘制了一层 alpha=1 的不可见底；`WindowFromPoint` 在条端（如右侧条顶部、右端）均返回本窗口，解决了分层窗口 alpha=0 区域点击穿透的问题。
- 贴边状态与位置写入 `%APPDATA%\AccelBall\config.ini`，重启后恢复。

## 5. 右键菜单、单实例与退出

- 右键球/贴边条弹出原生菜单：「立即清理内存」「开机自启」「退出」；自启项按 `AccelBall` 计划任务是否存在显示勾选，设置期间置灰。
- 第二实例 1 秒内退出（退出码 0）；开发版使用独立互斥名与 `config-dev.ini`，可与发布版并行。
- 优雅退出退出码 0；此前静态 GDI+ `FontFamily` 在 `GdiplusShutdown` 后析构导致 0xC0000005，已改为进程级不析构指针，复测通过。

## 6. 开机自启

- 程序内实现：右键 →「开机自启」勾选即创建计划任务，取消勾选即删除；状态改变期间球上显示「设置自启」，完成后显示「自启已开」「自启已关」或「自启失败」。
- 任务参数：名称 `AccelBall`；动作 `C:\Program Files\AccelBall\AccelBall.exe`；触发器登录时；`RunLevel = Highest`；`LogonType = Interactive`；通过 `schtasks` 的 `/IT /RL HIGHEST /RU <当前用户>` 创建，登录时不会弹 UAC。
- 管理员探针测试（临时任务，不影响真实任务）：

```text
query before          → exists=0
create via module     → set=1
query after create    → exists=1
delete via module     → set=1
query after delete    → exists=0
direct schtasks create/query/delete → exit 0
```

- 现有任务核对：`AccelBall` 状态 `Ready`，`UserId = PC`，`RunLevel = Highest`，`LogonType = Interactive`，触发器用户 `ADMINISTRATOR\PC`。
- 任务在用户登录后启动，不在登录前运行（GUI 程序需要桌面会话）。
- 安装包的 `[UninstallRun]` 已加入 `schtasks /Delete /TN "AccelBall" /F`；未执行实际卸载测试（会删除当前安装）。

- manifest 为 PerMonitorV2；代码处理 `WM_DPICHANGED`、`WM_DISPLAYCHANGE`、`WM_SETTINGCHANGE(SPI_SETWORKAREA)`，按最近显示器工作区定位并夹取。
- 开发版用 `ACCELBALL_DPI` 强制缩放实测（不改系统设置、发布版不读取该变量）：

| 96 | 74px | 11.4 MB / 2.5 MB / 5 |
| 120 | 93px | 11.6 MB / 2.6 MB / 5 |
| 144 | 111px | 11.6 MB / 2.5 MB / 5 |
| 192 | 148px | 11.7 MB / 2.6 MB / 5 |

- 150% 下截取 111px 球和 45×111 竖条，文字无裁切。
- 本机只有 100% 单屏，真实「跨显示器 DPI 切换」和多显示器硬件场景未实测。

## 8. 网速精度对照

- `tools/net_probe.cpp` 打印每块接口的 `HardwareInterface`、状态、累计字节与过滤结果。
- 本机 `GetIfTable2` 返回大量 WFP/QoS 过滤接口和虚拟接口：only `WLAN`（Intel Wi-Fi 6 AX200，type=71，hw=1，up=1）进入求和；FlClash/Meta Tunnel（hw=0）、WFP/QoS 过滤接口（hw=0）、loopback、WAN Miniport 均被排除，**没有重复计数**。
- 用 curl `--limit-rate 2m` 下载 24 MB：curl 自身平均 1,998,686 B/s；同一秒探针读到 WLAN 合计 23,705,821 B/s，界面显示 22.3 M/s。差额来自其他进程的真实流量（探针与界面一致），说明显示的是全主机物理网卡合计，不是单进程流量。
- 结论：计数逻辑与系统累计字节一致；高读数可能是其他应用/系统更新造成，不是悬浮球重复统计。

- 1.0.0 → 1.1.0 覆盖升级：旧实例通过 `taskkill` 优雅关闭（PID 38692），静默安装 `/VERYSILENT /SUPPRESSMSGBOXES /NORESTART` 退出码 0，随后启动新版。
- 安装结果：`C:\Program Files\AccelBall\AccelBall.exe` 242,688 字节、FileVersion 1.1.0、`README.md` 7,207 字节、`unins000.exe`；开始菜单组「加速球」含「加速球.lnk」「卸载加速球.lnk」。
- 新版启动：PID 37304，窗口 74×30 @ (1480, 0)，Working Set 11,868 KB；按保存的配置以顶部横向条启动。
- 提权窗口无法被非提权截图工具捕获（Windows UIPI 预期行为），发布版界面由用户目视验收；功能代码与开发版一致。

## 10. 未覆盖项

- 多显示器硬件场景与真实跨屏 DPI 切换未实测；只用强制 DPI 验证了布局缩放。
- 高负载网速精度依赖全主机流量，未做逐进程归因（工具本身只显示全主机合计）。
- 本机未做清理前后的性能 A/B 测试；内存清理不保证提速。
- 1.1.0 长跑内存/线程稳定性未复测；旧版长跑实例曾见 59 MB / 39 MB private / 16 线程。
- 安装包的卸载清理自启任务已写入脚本，但未执行实际卸载；发布版的自启勾选状态由用户目视确认（UIPI 限制）。
- 未做托盘图标、皮肤、多语言等扩展。
